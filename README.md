# ValutaTrade Hub

Итоговый проект **finalproject_Zagorniakova_M26_555**. Консольный симулятор торговли
фиатными и криптовалютами. Python ≥ 3.12, uv, requests, prettytable, Ruff, pytest.
Все кошельки и сделки виртуальные. Денежные значения считаются через `Decimal`.

## Быстрый запуск в Windows / VS Code

Откройте эту папку в VS Code → Terminal → New Terminal (PowerShell):

```powershell
$env:PYTHONUTF8 = "1"
uv sync --locked
uv run valutatrade
```

Альтернатива: `uv run python main.py`. Без аргументов открывается интерактивная
консоль. Сессия входа живёт в памяти одного процесса. Поэтому register/login/buy
выполняйте внутри одной консоли, а не отдельными вызовами программы.

В VS Code подготовлены задачи запуска, тестов, Ruff, сборки и демо; запуск отладчика —
F5 (с установленными расширениями Python и Python Debugger). Для форматирования
редактором можно установить расширение Ruff. Для самого приложения они не нужны.

## Настоящие API и ключи

Для криптовалют доступен CoinGecko. При необходимости задайте его Demo API key.
Для фиатных валют получите собственный ключ ExchangeRate-API:

```powershell
$env:EXCHANGERATE_API_KEY = "ваш-ключ"
# Необязательно:
$env:COINGECKO_API_KEY = "ваш-demo-ключ"
uv run valutatrade
```

Ключи читаются из переменных окружения при создании клиента. `.env.example` —
памятка, автоматической загрузки `.env` нет. `.env`, реальные JSON, логи и сборки
исключены из Git. Пароли вводятся скрыто, если не передать `--password`.
Параметр `--password` оставлен для совместимости с ТЗ и учебного демо.

Документация источников:
[ExchangeRate-API Standard Requests](https://www.exchangerate-api.com/docs/standard-requests),
[CoinGecko Simple Price](https://docs.coingecko.com/reference/simple-price).
Клиент ExchangeRate-API читает официальный `conversion_rates`, а также `rates`
из примера ТЗ. Ответ USD→EUR инвертируется: при 0.8 EUR за доллар получаем
`EUR_USD = 1.25`, а не 0.8. Криптовалюты запрашиваются по ID bitcoin/ethereum/solana.

## Команды интерактивной консоли

```text
register --username alice
login --username alice
show-portfolio
deposit --amount 1000
update-rates
show-rates
buy --currency BTC --amount 0.001
sell --currency BTC --amount 0.0004
show-portfolio --base USD
get-rate --from USD --to BTC
show-rates --currency RUB
show-rates --top 2 --base EUR
update-rates --source coingecko
currencies
help get-rate
logout
exit
```

Стоимость покупки зависит от текущего курса: 1000 USD может не хватить. Команды
`help` и `help <команда>` показывают все аргументы. `exit` запрашивает подтверждение;
Ctrl+C/Ctrl+Z+Enter также завершают консоль. `shlex` только разбирает введённую
строку, команды операционной системы не запускаются. Используйте обычные двойные
кавычки для имён с пробелами.

| Команда | Назначение |
|---|---|
| `register --username NAME [--password PASS]` | Уникальный пользователь и пустой портфель |
| `login --username NAME [--password PASS]` | Вход в текущую сессию |
| `show-portfolio [--base CODE]` | Балансы и общая стоимость |
| `deposit --amount N` | Явное пополнение виртуальных USD |
| `buy --currency CODE --amount N` | Покупка N единиц за USD |
| `sell --currency CODE --amount N` | Продажа N единиц с зачислением USD |
| `get-rate --from CODE --to CODE` | Прямой, обратный или кросс-курс |
| `update-rates [--source coingecko\|exchangerate]` | Все источники или один |
| `show-rates [--currency CODE] [--top N] [--base CODE]` | Свежие курсы из кэша; top — только криптовалюты |
| `currencies`, `logout`, `help [COMMAND]`, `exit` | Справочник и управление сессией |

Реестр: USD, EUR, GBP, RUB, BTC, ETH, SOL. Коды нормализуются в верхний регистр.
Сумма должна быть положительной и конечной; `NaN`, `Infinity`, `bool`, отрицательные
значения и перерасход отклоняются. Пустой портфель не требует сетевого запроса.

### Принятые решения по неоднозначностям ТЗ

В описании модели покупка списывает USD, а в описании команды встречается простое
пополнение актива. Здесь последовательно применяется модель настоящего обмена:
покупка списывает `amount × rate` USD, продажа зачисляет эту сумму в USD.
Регистрация создаёт **пустой** портфель; для старта есть отдельная команда `deposit`.
USD служит расчётной валютой: `buy/sell USD` отклоняются, для пополнения есть deposit.
Недостающий продаваемый кошелёк трактуется как нулевой баланс; ошибка сообщает
доступное и требуемое количество. Числа балансов в JSON записаны строками, чтобы
точные десятичные значения не терялись при сериализации; читаются и числовые значения.

## Архитектура

```text
valutatrade_hub/
  core/
    models.py          User, Wallet, Portfolio
    currencies.py      ABC Currency, FiatCurrency, CryptoCurrency, get_currency
    exceptions.py      доменные ошибки
    utils.py           валидация, UTC, замыкание ttl_cache
    rates.py           TTL, обратные и кросс-курсы
    usecases.py        регистрация, вход, портфель, операции
  infra/
    settings.py        Singleton SettingsLoader, конфигурация
    database.py        Singleton DatabaseManager, JSON и блокировки
  parser_service/
    config.py          env-ключи, URL, валюты, таймаут
    api_clients.py     ABC BaseApiClient, два HTTP-клиента
    updater.py         независимый опрос источников
    storage.py         история и текущий снимок
    scheduler.py       отдельный запуск и периодическое обновление
  cli/interface.py     парсинг аргументов, сообщения, таблицы
  decorators.py        @log_action, @confirm_action
  logging_config.py    ротация UTF-8 логов
data/                  runtime JSON и безопасные пустые *.example.json
tests/                 изолированные автоматические сценарии
scripts/demo.py        воспроизводимое демо
docs/                  запись, проигрыватель, критерии и проверка
main.py, pyproject.toml, uv.lock, Makefile
```

CLI вызывает usecases, не меняя кошельки напрямую. Core читает локальные курсы;
при отсутствии свежего курса инициирует одно обновление Parser Service. Парсер
можно запускать отдельно от CLI. Singleton реализован через `__new__` с блокировкой:
это простой явный способ получить один экземпляр; импорты экземпляров не создают.

## Данные, сохранение и пароли

На первом запуске создаются `users.json`, `portfolios.json`, `rates.json`,
`exchange_rates.json`, `transactions.json`. Реальные файлы не отслеживаются Git;
пустые примеры структуры находятся рядом. Рабочая папка по умолчанию — текущая.

`users.json` хранит ID, имя, SHA-256(password + salt), случайную индивидуальную
соль и дату регистрации ISO UTC. Открытый пароль не сохраняется и не логируется.
SHA-256 выбран по требованию учебного ТЗ; для реального сервиса следует заменить
его на специализированный password KDF (например, Argon2id).

Запись JSON: временный файл в той же папке → flush/fsync → `os.replace`.
Межпроцессная блокировка защищает чтение–изменение–запись. Журнал `.pending.json`
позволяет завершить запись связанных файлов после прерывания процесса. Регистрация
сохраняет пользователя вместе с портфелем, сделки — портфель вместе с историей.
Повреждённый JSON не перезаписывается пустыми данными. При ошибке диска во время
коммита он может завершиться при следующем обращении: перед повтором операции
проверьте портфель и `transactions.json`.

Это локальное файловое хранилище для учебного проекта. История растёт без обрезки;
для большого сервиса потребуются БД и резервные копии. Файлы с данными пользователей
следует хранить в каталоге с доступом только владельца компьютера.

## Кэш, TTL и история курсов

`data/rates.json`:

```json
{
  "pairs": {
    "EUR_USD": {"rate": 1.25, "updated_at": "2026-10-31T12:00:00Z", "source": "ExchangeRate-API"}
  },
  "last_refresh": "2026-10-31T12:00:01Z"
}
```

Курс — количество TO за одну FROM. USD→BTC рассчитывается как обратный BTC→USD;
BTC→EUR — как BTC→USD / EUR→USD. У кросс-курса используется более старая из двух
меток. `RATES_TTL_SECONDS = 300` задан в `[tool.valutatrade]` в `pyproject.toml`.
При возрасте ≥ TTL курс не используется для сделки. Core пытается обновить данные
один раз, затем выдаёт понятную ошибку. `show-rates` показывает только свежий кэш
и самостоятельно в сеть не обращается; при устаревших данных предлагает обновление.

`updated_at` — момент успешного получения данных парсером, TTL измеряет свежесть
локального получения. Исходная дата поставщика сохраняется отдельно в
`exchange_rates.json → meta.source_updated_at`, если API её предоставляет.
В частности, ежедневный фиатный курс может иметь исходную дату старше времени
получения. `request_ms`, `status_code`, `etag` и `raw_id` сохраняются в meta.
История имеет ID `FROM_TO_TIMESTAMP`; дубликаты не добавляются, старый замер
не заменяет более свежий снимок. Неудачный источник не удаляет его прежние пары.
Если все источники недоступны, файлы курсов не меняются. Статус частичного обновления
явно выводится пользователю и даёт ненулевой код завершения.

В памяти JSON дополнительно кэшируется замыканием на одну секунду, с инвалидацией
по размеру/времени изменения файла. Проверка возраста курсов выполняется при каждом
обращении, поэтому этот кэш не продлевает TTL котировки.

## Отдельный Parser Service

```powershell
uv run valutatrade-parser --source coingecko
uv run valutatrade-parser --interval 300
```

Первый вариант обновляет один раз, второй повторяет через заданный интервал после
завершения запроса до Ctrl+C. Для системного расписания можно использовать Windows
Task Scheduler с однократной командой, рабочей папкой проекта и нужными env-ключами.
HTTP-запросы имеют таймаут 10 секунд. Сеть, HTTP 401/403/429/5xx, неверный JSON
и некорректные числовые курсы преобразуются в `ApiRequestError`. Сырые тексты
сетевых исключений и URL с ключами не попадают в журналы.

Пути можно вынести из папки проекта:

```powershell
$env:VALUTATRADE_HOME = "C:\\MyValutaTrade"
$env:VALUTATRADE_DATA_DIR = "C:\\MyValutaTrade\\data"
$env:VALUTATRADE_LOG_DIR = "C:\\MyValutaTrade\\logs"
```

`VALUTATRADE_HOME` также задаёт место поиска `pyproject.toml`. Без файла используются
значения по умолчанию. После изменения конфигурации перезапустите приложение.

## Логирование и ошибки

`logs/actions.log` содержит timestamp UTC, action, user_id, currency_code, amount,
rate, base, result; при ошибках — error_type/error_message. Декоратор не подавляет
исключения. Для сделок verbose добавляет балансы до/после и длительность.
`logs/parser.log` содержит этапы опроса источников и сохранения. Уровень INFO,
ротация по 1 MiB, три резервных файла; параметры задаются в конфигурации.

Недостаток средств → сообщение с остатком; неизвестная валюта → список кодов;
неавторизованная операция → предложение login; недоступный курс → update-rates
и проверка сети/ключа; неверные аргументы → ошибка без завершения интерактивной сессии.

## Проверки и сборка

```powershell
uv run ruff check .
uv run ruff format --check .
uv run pytest --cov=valutatrade_hub --cov-report=term-missing
uv build
```

Сборка создаёт wheel и sdist в `dist/`. Пакет включает `valutatrade_hub` и две
консольные точки входа. После установки wheel работа возможна из любой выбранной
папки; данные создаются в ней. README, тесты и демо входят в исходный репозиторий.

Для GNU Make есть цели `install`, `run`, `lint`, `format`, `test`, `build`, `demo`,
`parser`. В Windows без Make используйте команды выше или задачи VS Code.

Тесты используют временные папки и подготовленные HTTP-ответы: сеть и ключи
не нужны, личные данные не затрагиваются. Проверяются модели, сериализация,
пароли, полный торговый цикл, изоляция пользователей, неизменность данных при
отклонённой сделке, обратные/кросс-курсы, TTL, HTTP-ошибки, частичный отказ,
дедупликация истории, восстановление записи, параллельные процессы, CLI и логи.

## Демонстрация и критерии

Откройте [docs/demo.html](docs/demo.html) в браузере — готовая анимация команд.
Запись asciinema v2: [docs/demo.cast](docs/demo.cast), текст: [docs/demo.txt](docs/demo.txt).
При установленной asciinema: `asciinema play docs/demo.cast`.
Для повторного создания:

```powershell
uv run python -m scripts.demo
```

Демо исполняет настоящий CLI с **учебными HTTP-ответами**, а не живыми ценами.
Оба реальных API-клиента выполняют обычный разбор этих ответов. Данные демо
изолированы во временной папке. Запись показывает регистрацию, вход, покупку,
продажу, портфель, курсы, оба источника обновления и ошибки.
Код проверяет итог: 640 USD + 0.006 BTC × 60000 = 1000 USD.

Соответствие всем семи блокам на 50 баллов: [docs/criteria.md](docs/criteria.md).
Результаты фактической проверки: [docs/verification.md](docs/verification.md).
Окончательную оценку выставляет преподаватель.
